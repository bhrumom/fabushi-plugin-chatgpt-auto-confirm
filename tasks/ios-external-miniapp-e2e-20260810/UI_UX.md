# UI/UX 与可测试性要求

## 薄 UI 原则

iOS/Flutter 只呈现 CLI 状态并把用户意图映射为 CLI 命令。搜索结果、安装状态、版本、更新、会话和错误不得由 UI 自行伪造或维护第二份状态机。

## 自动化语义

- 登录、市场搜索框、搜索结果、安装/更新按钮、已安装列表、机器人会话、消息输入与发送动作提供稳定语义 key。
- 自动化通过语义和 CLI 状态条件定位，不依赖坐标、中文文案或动画时长。
- 等待界面完成必须同时满足对应 CLI/runtime 终态；UI 上的 toast、按钮变化或回复气泡不能单独判定成功。

## 核心场景

1. 启动干净测试 profile，确认插件列表为空。
2. 输入“全球法布施”，展示来自正式市场的唯一可识别结果。
3. 安装外部构件，界面呈现 CLI 验证与安装终态。
4. 检测新版本并热更新，宿主 App 不重新安装。
5. 打开机器人会话，发送确定性消息并显示真实插件响应。
6. 测试用 correlation id 从 UI 操作追溯到 CLI、安装器和插件 runtime 证据。

失败时 UI 应呈现可操作且脱敏的状态；完整诊断由测试 harness 导出，不在界面泄露令牌、路径或原始敏感数据。
